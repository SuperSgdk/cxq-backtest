# 数据字段与时间约定

公开仓库不分发历史行情。用户自行准备有使用权限的数据，本框架负责读取和检查格式。样例目录里的文件是人工构造的手算测试场景，不能冒充采购行情或历史成绩。

## 行情文件

`load_market_data(path_or_dataframe)` 接受 CSV / Parquet 路径或 DataFrame。

每行对应一个交易日的一只股票。`date + code` 必须唯一，股票代码保留为字符串，不要让 CSV 工具去掉前导零。

至少需要两个交易日：第一天生成决定，后一天才有执行机会。当前接口要求每只股票覆盖文件中的同一交易日历；停牌需要显式行，上市前或退市后缺少交易日的标的应分窗口处理。

| 字段 | 含义与要求 |
|---|---|
| `date` | 日级日期，建议 `YYYY-MM-DD`，不含盘中时间 |
| `code` | 股票代码字符串，同一股票保持同一种表示 |
| `open` | 当日开盘价，有限正数 |
| `high` | 当日最高价，有限正数，不能低于开盘、收盘或最低价 |
| `low` | 当日最低价，有限正数，不能高于开盘、收盘或最高价 |
| `close` | 当日收盘价，有限正数 |
| `volume` | 当日成交量，非负数，单位须在数据准备时统一 |
| `up_limit` | 当日涨停价，有限正数，与 OHLC 使用同一价格口径 |
| `down_limit` | 当日跌停价，有限正数，与 OHLC 使用同一价格口径 |
| `is_st` | 当日 ST 标记，使用布尔值或 `0` / `1` |
| `is_suspended` | 当日停牌标记，使用布尔值或 `0` / `1` |

缺字段、缺值、重复行、非有限价格和不合理 OHLC 不应靠默认值掩盖。加载函数会检查这些输入问题；如报错，应修正数据来源或准备过程。

整根日线须位于提供的价格上下限内：`high <= up_limit`、`low >= down_limit`，同时开盘价位于上下限之间。

### 停牌与缺行

停牌使用显式行和 `is_suspended=1` 表达；不要把“找不到股票记录”猜成停牌。停牌行的价格应来自此前已知的有效估值，而不是填写零或使用将来的复牌价。成交量可以为 0。

具体校验要求是 `volume=0`，且 `open=high=low=close`；窗口内已有此前有效收盘价时，停牌估值须与其一致。

已有持仓停牌时，框架使用此前有效收盘价估值，禁止买卖。因为卖出失败，该部分资产不会转为现金。停牌状态和涨跌停价都应由用户合法持有的数据提供，框架不会联网补采。

### 价格口径

OHLC、涨跌停价及策略使用的其他价格必须同口径。不能把复权 OHLC 与未复权涨跌停价混用。

v0.1 不处理分红、送转、拆股等公司行为。如果数据窗口覆盖这些事件，应先确认选用的价格口径与建模目的是否相容；框架不会自动恢复真实股数和现金分配。

## 目标权重文件

`load_target_weights(path_or_dataframe)` 接受 CSV / Parquet 路径或 DataFrame，返回按日期组织的代码到权重映射。

| 字段 | 含义与要求 |
|---|---|
| `date` | 策略做出决策的日期，即 T 日收盘后的日期 |
| `code` | 与行情中的股票代码一致 |
| `weight` | 目标资产比例，非负有限数；总目标权重不能超过 1 |

例如，`0.3` 表示目标占账户资产的 30%，不是排名、评分或成交概率。目标比例会受整手、费用、可用现金和交易限制影响，实际持仓可能达不到目标。

- 某日没有任何清单：当天不主动调仓，保留已有持仓，其他已配置的交易规则仍按实现处理。
- 给出某日完整非空清单：按清单调仓，未列入的已有持仓尝试退出。
- 清单里某股票为 `0`：尝试退出该股票，仍需通过 T+1、停牌和跌停等检查。

如需明确清仓，应对已有标的列出 `0` 权重；不要靠省略整个日期来表达清仓。

每次计划只在下一交易日尝试一次。若目标订单因交易限制被拒，之后需要策略重新给出计划；框架不把旧拒单自动顺延为下一日订单。未成交持仓继续估值，其他已配置的风控规则单独处理。

## 可复现与发布

回测结果保存输入内容指纹和配置。相同文件名不代表相同数据；比较结果时应检查指纹、日期窗口、费率和策略参数。

采购行情、由采购行情导出的逐票记录与其他授权不明的数据，不应随框架公开分发。运行产生的 `outputs/`、本地 `data/` 和日志默认忽略。公开检查脚本是补充检查，数据分发权仍需单独确认。
