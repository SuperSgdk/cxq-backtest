# 框架架构

本项目解决的问题是：给定行情、策略和资金，按明确的交易限制与费用计算账户变化，并保留可核对的成交记录。它不负责采购行情，不生成私有评分，也不把信号自动发到证券账户。

## 输入、处理与输出

```text
用户授权使用的日级行情 + 策略 + 回测设置
                   ↓
              校验数据字段
                   ↓
           T 日收盘产生目标权重
                   ↓
        下一交易日开盘检查交易限制
                   ↓
          成交、费用和持仓记账
                   ↓
             收盘资产估值
                   ↓
      绩效指标 + 净值 + 成交 + 订单原因
```

`cxq_bt.framework.run_backtest()` 是公开版的统一入口。命令行、Python 调用和 Streamlit 界面共用该入口，避免各自计算费用或收益。

## 模块为什么存在

| 模块 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 数据加载与校验 | CSV / Parquet / DataFrame | 检查必需字段、时间、价格、标记与重复行 | 可按交易日访问的行情 |
| 策略接口 | 仅截至当前决策日的历史 | 生成目标权重，或声明该日不调仓 | 代码到权重的映射 / `None` |
| 费用模型 | 数量、参考价、费率 | 滑点、最低佣金、卖出印花税与过户费 | 成交价及费用 |
| 交易规则 | 持仓、行情、买入日期 | T+1、整手、ST、停牌和涨跌停检查 | 可以成交 / 受限原因 |
| 执行与记账 | 目标权重、现金、可交易持仓 | 先退出，再按可用现金尝试买入 | 成交和实际持仓 |
| 绩效计算 | 每日权益与成交记录 | 计算收益、回撤与其他统计量 | 汇总指标 |
| 可视化 | 回测结果 | 展示曲线和记录、导出文件 | 用户可检查的结果页面 |

底层扩展基于 Backtrader，相关费用和规则也可作为独立组件使用。项目不把 Backtrader 的已有能力表述为本项目原创。

## 时间与现金约束

策略在 T 日收盘后决策。它可以查看当天完整日线，但只在下一个行情交易日开盘执行。这意味着当天收盘结果不会被用于当天开盘买入。

停牌必须在输入中显式标记。停牌持仓使用此前有效收盘价估值，并保持其资产属性。跌停或其他原因导致卖出失败时，资产仍被占用，不能把计划卖出的金额提前用于买入。

每次目标计划只在下一交易日尝试一次，拒单不自动延续为下一天订单。再次尝试需要策略重新给出目标计划；是否因风控规则另行产生退出订单，应按对应配置判断。

若最后一个交易日产生信号，文件里没有下一交易日的开盘，则没有执行机会；不能假定存在下一日成交价。

## 配置与结果

`BacktestConfig` 管理 `initial_cash`、`costs`、`lot`、`max_positions`、`exclude_st`、`hard_stop_pct`。实际默认值与校验以接口定义和 `--help` 为准。初始资金必须大于 0，费用参数应与使用场景一致。

`BacktestResult` 包含：

- `summary`：期末权益、收益、回撤、年化收益、Sharpe、费用与成交笔数等指标。
- `equity`：每日账户权益，用于核对净值曲线。
- `trades`：实际发生的买卖记录。
- `orders`：订单执行状态，以及未成交原因。
- `settings`：输入指纹、策略与成交模型等设置。

`to_dict()` 将这些信息转换成可以保存或展示的结构。输入指纹用于识别输入内容，并不替代数据许可或数据质量核验。

## 当前模型的边界

公开主入口是日级模型。涨跌停和停牌规则只能按输入中已有的标记与价格进行判断，无法模拟真实盘口深度、排队次序或冲击成本。固定滑点也只是可配置近似。

v0.1 不处理分红、送转、拆股和其他公司行为，不承诺日级模型能恢复这些事件的真实资金与持仓变化。行情与涨跌停价应保持相同价格口径，使用者必须为其数据的复权处理负责。

人工构造的 CSV 只证明测试情形下的计算行为。验证真实策略还需要有合法使用权的行情、完整数据检查、按时间划分的样本外检验及与策略对应的成交模型。
